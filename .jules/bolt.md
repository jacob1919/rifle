## 2024-05-24 - Remove string allocations in happy path
**Learning:** In high-frequency parsing paths, constructing or concatenating `std::string` objects for error context (e.g., `field_name + ".size"`) on the "happy path" introduces significant unnecessary heap allocations and overhead. Initializing fixed-size buffers with zeros (`std::array<unsigned char, N> bytes{}`) when they are immediately and fully overwritten also wastes CPU cycles.
**Action:** When optimizing C++ string operations, defer allocations and concatenations strictly to the error handling path (e.g., inside the `throw` statement) by passing default arguments (`suffix`). Omit zero-initialization for buffers that will receive exact raw bytes. Also, use `value.resize(size)` on a default-constructed string instead of `std::string value(size, '\0')` to minimize zero-initialization overhead.
