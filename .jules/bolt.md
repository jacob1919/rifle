## 2024-10-11 - Optimize string allocation and concatenation in GGUF parsing
**Learning:** In high-frequency parsing paths, dynamically constructing strings and passing them by `const std::string&` (e.g., `std::string(field_name) + ".size"`) for error handling results in significant heap allocations and performance overhead. Furthermore, initializing strings with `std::string value(size, '\0')` to receive raw bytes zeros out memory unnecessarily.
**Action:** Use `std::string_view` for string parameters in the parsing critical path. Defer string concatenation to the error handling path (using a default `suffix` parameter) to avoid allocations on the happy path. Note: Using `std::string::resize(size)` instead of `std::string(size, '\0')` does not avoid zero-initialization overhead in C++20, so that specific micro-optimization attempt was a placebo.
