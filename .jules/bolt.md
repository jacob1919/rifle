## 2023-10-18 - Avoid String Allocations in High-Frequency C++ Parsing Code
**Learning:** In C++ parsing routines (like `read_little_endian` or `read_exact` in `gguf_parser.cpp`), constructing `std::string` on the happy path (e.g., passing `"field_name.size"` as a parameter which constructs a temporary `std::string`) causes significant overhead due to memory allocation and deallocation (`malloc`/`free`). Profiling with Callgrind showed an instruction count (Ir) reduction of ~50 million (from ~148M to ~98M) just by modifying the parameters to accept `std::string_view` and avoiding concatenation strings on the happy path.
**Action:** When implementing parsing or generic utility functions in C++, prioritize `std::string_view` over `std::string` for parameters, and defer any string construction (like error message formatting) to the error-handling path (`throw` block).
