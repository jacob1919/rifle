## 2024-07-04 - [Performance Pattern: std::string_view for string literal parameters]
**Learning:** Found a common performance pitfall in the GGUF parsing logic. Helper functions (like `read_little_endian`) accepting string arguments were typed as `const std::string& field_name`. When these functions are called with string literals (e.g., `read_little_endian<uint32_t>(input, "version")`), this forces an implicit heap allocation to construct the `std::string` object before passing it by reference. In high-frequency parsing paths, this generates significant overhead.
**Action:** Changed the parameter types in internal C++ helpers to `std::string_view` to completely avoid allocations when passing string literals. Will look for `const std::string&` in function signatures specifically meant for string literals to optimize further.
