## 2024-05-24 - Remove string allocations in happy path
**Learning:** Constructing and concatenating std::string error contexts like `field_name + ".size"` during frequent operations (like `read_little_endian` parsing GGUF arrays) creates significant heap allocation overhead on the happy path, causing millions of unnecessary instruction executions.
**Action:** When implementing parsing functions that require error messages, avoid building dynamic strings in the happy path. Pass lightweight `std::string_view` arguments (e.g. `field_name` and an optional `suffix`) and defer the actual `std::string` concatenation exclusively to the error handling path (inside the `throw`). Avoid zero-initializing strings before reading raw bytes (`std::string value; value.resize(size)`) to save CPU cycles.
